# 知识卡片制作

把一篇文章拆成 5–8 张能独立理解、可复习的知识卡片。每张卡片只承载一个知识点，全部内容必须来自原文。

## 读取输入

- 用户粘贴文本时，以该文本为唯一来源。
- 用户给出本地 `.md` / `.txt` 路径时，先读取全文再开始。
- 用户给出网页链接、PDF、图片，或要求 Anki 导出、图形界面时，说明暂不支持，请其粘贴正文或提供 md/txt 文件。不要尝试抓取、转换或猜测内容。
- 输入过短（不足约 300 字）、只有标题或口号时，如实说明信息量不足以拆出 5 张，最多输出 1–3 张，并请用户补充内容。不要用常识补齐。

## 制作流程

### 1. 通读并标记候选点

逐段找出：中心主张、定义、因果机制、关键数字、操作步骤、判断标准、常见误区、适用边界。

### 2. 按重要性排序

保留优先级从高到低：

1. 文章的中心论点或结论
2. 解释「为什么」的机制与因果链
3. 有上下文的关键数字、阈值、对比
4. 可执行的步骤、方法、清单
5. 反直觉之处、常见误区、适用条件

删除：例子里的细节铺陈、背景铺垫、重复表述、过渡句、作者情绪、广告与无关内容。

### 3. 去重合并

同一知识点在多处出现时只保留最完整的一处；互为前提、分开就讲不通的两句话合成一张卡片。合并后若仍含多个中心，再拆分，保证一张卡片只说一件事。

服务于同一目标的连续步骤（如一套配置流程、一组操作清单）算一个知识点，合成一张卡片，不要按步骤数量拆卡凑数。

### 4. 确定数量

- 候选点不少于 5 个：输出 5–8 张，优先 5–6 张，宁少勿滥。
- 候选点少于 5 个：按实际数量输出（1–4 张），并在开头写明「原文可提炼的知识点只有 N 个」。
- 绝不为凑数把同一知识点拆成多张，也不添加原文没有的内容。

### 5. 写卡片

每张卡片固定四段：

```
### 卡片 N：<具体标题>

**核心知识**：<一句话结论，25–60 字，脱离上下文也能成立>

**简明解释**：<它是什么、为什么成立、怎么用，2–3 句>

**例子 / 自测**：<原文中的例子，或一道能用本卡片回答的自测题>
```

字段写法：

- **标题**：写可检索的主题，避免「第一点」「介绍」这类空标题；卡片之间标题不能重复。
- **核心知识**：这张卡片唯一要记住的结论，用陈述句写，一句话只放一个结论。
- **简明解释**：补足理解所需的背景与因果，但不引入原文没有的事实、数据或类比。原文说法模糊时保持模糊，不要替作者下更强的结论。
- **例子 / 自测**：优先压缩原文例子到 1–2 句且不改动事实；原文没有例子时写一道自测题，答案必须能在本卡片中找到，不要虚构案例。
- 自测题只考原文明确写出的内容。原文只给现象、配置或结论时，不要用常识补出「为什么」，改问「原文怎么说」「原文怎么做」。答案的措辞强度要与原文一致，不能把「更重要」写成「不能替代」，把「关系密切」写成「决定」。

格式示例（仅示结构，不代表任何原文）：

```
### 卡片 1：复述比重复阅读更能留住内容

**核心知识**：合上材料主动复述，比反复阅读更能形成长期记忆。

**简明解释**：重复阅读带来熟悉感，容易高估掌握程度；复述迫使大脑提取信息，提取过程本身会强化记忆。

**例子 / 自测**：读完一节后合上资料，用自己的话写出三个要点，再对照原文补漏。
```

## 事实边界（硬性）

- 所有数字、人名、时间、结论都要能在原文找到对应表述；可以改写，不可增补。保留原文的单位与量级，不擅自换算。
- 不补充领域常识，不做外部检索，不推断作者没说的因果。原文没有解释原因时，卡片里就不要写原因。
- 不放大结论强度。原文说「更重要」「关系最密切」「通常」，不要改写成「必须」「决定性」「完全替代」。
- 原文前后矛盾时，在卡片中标注「原文前后说法不一致」，不要自行裁决。
- 原文是观点而非事实时，写成「作者认为……」，不要当作客观结论。
- 输出语言与原文一致。

## 输出格式

开头一行写 `共 N 张卡片`；少于 5 张时补充一句原因。随后按顺序输出卡片，卡片之间空一行。

不要添加寒暄、全文摘要、总结段或延伸阅读。用户明确要求表格、JSON、写入文件时按用户要求输出，否则只用上述 Markdown 结构。

## 交付前自检

逐项检查，任一不通过就修改：

1. **事实**：每句话都能在原文定位，没有新增信息。
2. **单点**：每张卡片只有一个中心，标题不重复。
3. **去重**：没有两张卡片讲同一件事。
4. **数量**：5–8 张；少于 5 张时已说明原因。
5. **完整**：四段齐全，例子或自测题存在。
